# workflows/

Markdown SOPs. Plain language, the way you'd brief a teammate.

## Index

| Workflow | Objective |
|---|---|
| `build_learning_roadmap.md` | Research and install the AI-engineer learning roadmap (run once) |
| `create_lesson.md` | Research and write one lesson page, then rebuild the site |
| `log_session_progress.md` | Record a study session — streak, completion, what was built |
| `refresh_roadmap.md` | Quarterly: re-check the roadmap and lessons against current reality |
| `_TEMPLATE.md` | Starting point for new workflows |

## Conventions

- One file per workflow, named for the job: `scrape_website.md`, `weekly_report.md`.
- Start from `_TEMPLATE.md` — objective, inputs, tools, steps, output, failure handling, notes.
- **Never create or overwrite a workflow without asking first.** These are instructions to be refined, not disposable.
- Keep the **Notes & learnings** section alive. Rate limits, timing quirks, undocumented API behavior — write it down the moment you learn it, dated.
- If a step needs judgment, describe the judgment. If it's mechanical, push it into a tool.
